Translations 🌍

Module: i18n.ts · Depends on: nothing

i18n is short for internationalisation (an i, 18 letters, an n). This module lets your app show its texts in the user’s language, keeping every text in JSON files instead of in the code.

In 30 seconds

Create resources/i18n/en/home.json:

{ "welcome": "Welcome!" }

…and resources/i18n/es/home.json:

{ "welcome": "¡Bienvenido!" }

Then:

import { setCurrentLanguage, loadTextBundle, getText } from "./gtd/i18n.js"

await setCurrentLanguage(navigator.language) // the browser's language, like "es-ES"
await loadTextBundle("home")

uiComponent({ type: "h1", text: getText("home", "welcome") }) // "¡Bienvenido!" in Spanish browsers

Where the files go

my-app/
├── index.html
└── resources/
    └── i18n/
        ├── en/
        │   ├── home.json
        │   └── settings.json
        └── es/
            ├── home.json
            └── settings.json
  • One folder per language (en, es…).
  • One JSON file per bundle: a group of texts, usually one per page or feature.
  • Each bundle has the same keys in every language.
  • resources/ sits next to index.html (paths are relative to the page). To use another folder, change I18N_PATH at the top of i18n.ts.

Splitting texts into bundles means each page only downloads the texts it needs.

The three functions

Function What it does
await setCurrentLanguage(locale) Chooses the language: "es", "es-ES", navigator.language…
await loadTextBundle(bundle) Downloads resources/i18n/<language>/<bundle>.json, once
getText(bundle, key) Returns the text, or "" if it’s not there

Load bundles before drawing the views that use them, for example at the start of the view:

setRoute("/settings", async (_, container) => {
  await loadTextBundle("settings") // does nothing if it is already loaded
  container.append(uiComponent({ type: "h1", text: getText("settings", "title") }))
})

Letting the user change language

await setCurrentLanguage("es", true) // true = download the loaded bundles again, in Spanish
navigate()                            // draw the current page again with the new texts

Remember the choice with Configuration, and use it at start:

setConfiguration("lang", "es")
// next time the app opens:
await setCurrentLanguage(getConfiguration("lang") ?? navigator.language)

Which languages are available

Out of the box, English, Spanish, Galician and Catalan can be used. Any other locale falls back to English, with a warning in the console.

To add a language, open src/gtd/i18n.ts and edit two places at the top:

export const Languages = {
  English: { name: "english", main: "en", locales: ["en", "en-US", "en-GB"] },
  Spanish: { name: "spanish", main: "es", locales: ["es", "es-ES"] },
  Galician: { name: "galician", main: "gl", locales: ["gl", "gl-ES"] },
  Catala: { name: "catala", main: "ca", locales: ["ca", "ca-ES"] },
  French: { name: "french", main: "fr", locales: ["fr", "fr-FR", "fr-CA"] }, // ← new
}

const AVAILABLE_LANGUAGES = [
  Languages.Spanish,
  Languages.English,
  Languages.Galician,
  Languages.Catala,
  Languages.French, // ← and enable it
]
Field Meaning
main The folder name under i18n/
locales Every code that should pick this language (navigator.language gives values like "fr-CA")

Then create resources/i18n/fr/ with the same bundles. To start in another language when the locale is unknown, change DEFAULT_LANGUAGE.

Texts with values inside

getText returns plain strings, so use placeholders and replace:

{ "greeting": "Hello, {name}!" }

getText("home", "greeting").replace("{name}", user.name)

When something is missing

Situation What you get
Bundle not loaded yet ""
Key not in the bundle ""
Bundle file missing or broken Skipped quietly; texts read ""
Retry a flaky network loadTextBundle("home", false, 3) tries up to 3 times

An empty text on screen almost always means a missing await loadTextBundle(...) or a typo in a key. Check the Network tab for a 404 on the JSON file.
